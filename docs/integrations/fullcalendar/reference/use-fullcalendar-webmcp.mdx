React hook that registers FullCalendar WebMCP tools against your host persistence.

## Signature

```ts
import { useFullCalendarWebMCP } from "@protocoltooling/fullcalendar";

function useFullCalendarWebMCP(options: FullCalendarWebMCPOptions): void;
```

      required: false,

    },
  }}
/>

## Example

```tsx
import FullCalendar from "@fullcalendar/react";
import { useCallback, useRef, useState } from "react";
import { useFullCalendarWebMCP, type CalendarEvent } from "@protocoltooling/fullcalendar";
import { repository } from "./events-service";

export function Calendar() {
  const calendarRef = useRef<FullCalendar>(null);
  const [events, setEvents] = useState<CalendarEvent[]>([]);

  const refreshEvents = useCallback(async () => {
    setEvents(await repository.list());
  }, []);

  useFullCalendarWebMCP({
    calendarRef,
    events: repository,
    onEventsChanged: refreshEvents,
    onRegistrationError: (error) => console.error(error),
  });

  return (
    <FullCalendar
      ref={calendarRef}
      events={events.map((event) => ({
        ...event,
        end: event.end ?? undefined,
      }))}
    />
  );
}
```

## Lifecycle

- **Registration:** Tools register in `useEffect`. Unmount aborts registration and cleans up.
- **Strict Mode:** Safe under development double-mount; no duplicate tools left behind.
- **Late WebMCP runtime:** If `document.modelContext` is missing at mount, the hook polls every 250 ms until it appears or the component unmounts.
- **Fresh options:** Tool handlers always use the latest `events` repository and callbacks without re-registering on every render.

See [`CalendarEventRepository`](/integrations/fullcalendar/reference/calendar-event-repository), [Types](/integrations/fullcalendar/reference/types), [Security](/integrations/fullcalendar/concepts/security), and [Troubleshooting](/integrations/fullcalendar/troubleshooting).

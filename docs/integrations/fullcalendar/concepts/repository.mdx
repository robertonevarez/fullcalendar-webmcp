title: Repository Contract

WebMCP calendar tools call an object you provide. That object implements [`CalendarEventRepository`](/integrations/fullcalendar/reference/calendar-event-repository)—five methods that wrap your existing API or database.

You pass it as the `events` option to [`useFullCalendarWebMCP`](/integrations/fullcalendar/reference/use-fullcalendar-webmcp).

Authorization and authentication are host-owned. The repository must enforce the same rules for agent and UI traffic. See [Security](/integrations/fullcalendar/concepts/security).

## Methods

| Method | Purpose |
|---|---|
| `list` | Return events, optionally filtered by range or title text |
| `get` | Return one event by id, or `null` |
| `create` | Persist a new event and return it with its id |
| `update` | Apply changes and return the updated event |
| `delete` | Remove an event by id |

```ts
export interface CalendarEventRepository {
  list(
    query?: CalendarEventQuery,
    options?: { signal?: AbortSignal },
  ): Promise<CalendarEvent[]>;

  get(
    id: string,
    options?: { signal?: AbortSignal },
  ): Promise<CalendarEvent | null>;

  create(
    input: CreateCalendarEventInput,
    options?: { signal?: AbortSignal },
  ): Promise<CalendarEvent>;

  update(
    id: string,
    input: UpdateCalendarEventInput,
    options?: { signal?: AbortSignal },
  ): Promise<CalendarEvent>;

  delete(
    id: string,
    options?: { signal?: AbortSignal },
  ): Promise<void>;
}
```

## Filters on `list`

```ts
export interface CalendarEventQuery {
  start?: string; // inclusive ISO 8601
  end?: string;   // exclusive ISO 8601
  text?: string;  // case-insensitive title substring
}
```

## Cancellation

Every method accepts an optional `{ signal?: AbortSignal }`. Forward it to `fetch` when you want aborted agent calls to cancel in-flight requests. Skip it until you need it.

## Any backend

REST, Server Actions, Supabase, Prisma, GraphQL, or an in-memory store for prototypes all work—as long as the same operations serve humans and agents.

For domain mapping and optional metadata, see [Custom event models](/integrations/fullcalendar/guides/custom-event-model). For why the host stays authoritative, see [Persistence](/integrations/fullcalendar/concepts/persistence).

---
title: Testing
description: Verify FullCalendar WebMCP tool discovery, event reads and mutations, UI refresh, and durable host persistence with a done-when checklist.
---

Use this checklist after the [Quickstart](/integrations/fullcalendar/quickstart) when you want a fuller smoke test.

## Done when

- [ ] Six `calendar_*` tools are registered in a WebMCP-capable browser
- [ ] `calendar_get_context` matches the on-screen view and timezones
- [ ] `calendar_list_events` matches visible events
- [ ] Agent create/update/delete updates the UI without a manual refresh
- [ ] Hard reload keeps agent mutations (host persistence works)
- [ ] A human edit in FullCalendar is visible to `calendar_get_event`

## Steps

<Steps>
  <Step title="Open in a WebMCP environment">
    Load your calendar in a browser or runtime that supports WebMCP.
  </Step>

  <Step title="Confirm tool registration">
    Check that these tools are present:

    - `calendar_get_context`
    - `calendar_list_events`
    - `calendar_get_event`
    - `calendar_create_event`
    - `calendar_update_event`
    - `calendar_delete_event`
  </Step>

  <Step title="Read context">
    Call `calendar_get_context`. Confirm `browserTimeZone`, `fullCalendarTimeZone`, `view`, and `visibleRange` match the UI.
  </Step>

  <Step title="List events">
    Call `calendar_list_events`. Confirm the list matches what FullCalendar shows.
  </Step>

  <Step title="Create a test event">
    Call `calendar_create_event`:

    ```json
    {
      "title": "Agent Test Meeting",
      "start": "2026-09-05T14:00:00Z",
      "end": "2026-09-05T15:00:00Z"
    }
    ```

    Confirm the tool returns an `event` with a non-empty `id`.
  </Step>

  <Step title="Confirm UI refresh">
    The new event should appear without a manual page reload (`onEventsChanged` ran).
  </Step>

  <Step title="Confirm durable persistence">
    Hard-reload the page. The test event should still be present.
  </Step>

  <Step title="Confirm human and agent share persistence">
    Drag or edit the test event in the FullCalendar UI, then call `calendar_get_event` with its id. The tool should return the updated times.
  </Step>

  <Step title="Delete the test event">
    Call `calendar_delete_event`. Confirm `{ "deleted": true }` and that the event leaves the UI immediately.
  </Step>
</Steps>

If a step fails, use [Troubleshooting](/integrations/fullcalendar/troubleshooting).
